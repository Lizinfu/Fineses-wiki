# 馆务公告更新与维护指南

这份指南适合负责发布通知、但不熟悉网站代码的维护者。日常更新公告时，不需要修改网页模板、样式或程序。

## 先认识两个公告位置

网站中有两个看起来相似、但作用不同的位置：

| 位置 | 读者在哪里看到 | 要编辑的文件 |
|---|---|---|
| 馆务公告页面 | 图书馆导航中的“公告”页面 | `content/library/notices/_index.md` |
| 首页公告弹窗 | 读者打开网站首页时出现的提示框 | `data/library/announcement.yaml` |

请特别注意：**这两个位置不会自动同步。**

- 只修改公告页面，不会自动改变首页弹窗。
- 只修改首页弹窗，也不会自动改变公告页面。
- 如果一条重要通知需要同时出现在两处，就要分别修改两个文件。

## 最常见的做法：更新公告页面

公告页面的文件是：

```text
content/library/notices/_index.md
```

打开后会看到类似内容：

```markdown
---
title: "馆务公告"
description: "公开访问、馆藏维护与读者服务的最新通知。"
weight: 70
---

这里是读者在公告页面看到的正文。
```

两组 `---` 之间是页面的基本信息，通常不用改：

- `title`：页面标题；
- `description`：页面标题下方的简短介绍；
- `weight`：页面在图书馆导航中的顺序。

日常发布通知时，只需修改第二组 `---` 下面的正文。

例如：

```markdown
---
title: "馆务公告"
description: "公开访问、馆藏维护与读者服务的最新通知。"
weight: 70
---

## 2026 年 9 月 19 日：馆藏检索维护

检索中心将于 9 月 21 日 14:00 至 16:00 进行维护。维护期间，部分搜索结果可能暂时无法打开，其他公开页面不受影响。

维护完成后，本页会及时更新。
```

### 同一页面保留多条公告

如果需要保留旧通知，可以把最新通知放在最上方，旧通知依次放在下面：

```markdown
## 2026 年 9 月 19 日：馆藏检索维护

最新通知的内容。

## 2026 年 8 月 20 日：读者留言开放

较早通知的内容。
```

建议每条公告都包含：

1. 日期；
2. 简短、明确的标题；
3. 发生了什么；
4. 什么时候开始和结束；
5. 哪些页面或服务会受影响；
6. 读者是否需要采取行动。

## 重要通知：同时更新首页弹窗

如果通知很重要，希望读者进入首页时立即看到，还要编辑：

```text
data/library/announcement.yaml
```

示例：

```yaml
enabled: true
id: "2026-09-search-maintenance"
kind: "notice"
title: "检索中心维护通知"
date: "2026-09-19"
summary: "检索中心将进行短时维护。"
body: "维护时间为 **9 月 21 日 14:00 至 16:00**，其他公开页面不受影响。"
cta_label: "查看完整公告"
cta_url: "/library/notices/"
```

各项含义如下：

| 项目 | 应填写什么 |
|---|---|
| `enabled` | `true` 表示显示弹窗，`false` 表示不显示。 |
| `id` | 这条弹窗的唯一标记。发布新通知时必须换成新值。 |
| `kind` | 公告类型。目前可写 `notice`、`warning` 或 `info`。 |
| `title` | 弹窗的大标题。 |
| `date` | 发布日期，建议使用 `年-月-日`，例如 `2026-09-19`。 |
| `summary` | 一句话概括通知。 |
| `body` | 弹窗正文，应保持简短，把详细内容放在公告页面。 |
| `cta_label` | 前往详细公告的按钮文字。 |
| `cta_url` | 按钮打开的页面。通常保持 `/library/notices/`。 |

### 为什么新公告一定要修改 `id`

读者关闭一条弹窗后，浏览器会记住“这条公告已经看过”。这个记忆以 `id` 为依据。

如果发布了新公告，却仍使用旧的 `id`，已经关闭过旧公告的读者可能看不到新公告。因此，每次发布新的首页弹窗，都要换一个从未使用过的 `id`。

推荐使用“日期 + 简短英文说明”，例如：

```yaml
id: "2026-09-search-maintenance"
```

请只使用英文字母、数字和短横线，不要使用空格。已经发布过的 `id` 不要重复使用。

## 如何撤下首页弹窗

通知结束后，将：

```yaml
enabled: true
```

改为：

```yaml
enabled: false
```

这样只会关闭首页弹窗，不会删除馆务公告页面中的历史内容。

建议不要直接删除 `data/library/announcement.yaml`，也不要把内容全部清空。保留原内容，日后重新启用时更容易参考。

## 可以使用的简单排版

公告页面和弹窗正文支持常见的 Markdown 写法。

```markdown
## 二级标题

普通段落。

- 第一项
- 第二项

**加粗内容**

[联系方式](/library/contact/)
```

在 `announcement.yaml` 中，如果文字包含英文冒号、井号或其他特殊符号，最安全的做法是像现有内容一样，用英文双引号包住整段文字：

```yaml
summary: "维护期间，搜索功能可能暂时不可用。"
```

文字本身需要出现英文双引号时，请联系熟悉 YAML 的维护者协助，避免文件格式错误。

## 发布前检查

修改完成后，按下面的清单检查：

- [ ] 公告日期和时间准确；
- [ ] 标题能让读者一眼看懂；
- [ ] 已说明受影响的服务或页面；
- [ ] 首页弹窗正文足够简短；
- [ ] 新弹窗使用了新的 `id`；
- [ ] `cta_url` 指向存在的页面；
- [ ] 没有修改 `public/` 中的文件；
- [ ] 提交前已经预览或运行内容检查。

如果本机已经配置好项目环境，可以在项目根目录运行：

```powershell
npm run wiki:validate
```

需要查看网页效果时，运行：

```powershell
npm run wiki:preview
```

然后按照终端显示的地址打开网站，检查首页弹窗和“馆务公告”页面。

## 常见问题

### 我改了公告页面，为什么首页弹窗没有变化？

公告页面和首页弹窗由两个不同文件控制。请同时修改 `data/library/announcement.yaml`。

### 我改了首页弹窗，为什么自己看不到？

浏览器可能记得你已经关闭过相同 `id` 的公告。发布新公告时，请确认已经使用新的 `id`。也可以用浏览器的无痕窗口检查。

### 通知结束后，历史公告要删除吗？

通常不用。可以关闭首页弹窗，并把旧公告保留在公告页面下方，方便读者查阅。如果旧通知已经完全失去参考价值，再从页面正文中删除。

### 可以直接修改 `public/library/notices/index.html` 吗？

不可以。`public/` 是网站构建时自动生成的目录，下次构建会覆盖其中的修改。应始终编辑 `content/library/notices/_index.md`。

### 可以改模板让公告显示得不一样吗？

日常公告维护不需要改模板。如果需要改变弹窗布局、颜色、按钮或行为，请交给网站开发维护者处理。

## 三种常见场景速查

### 普通通知，只放在公告页面

1. 编辑 `content/library/notices/_index.md`；
2. 不修改首页弹窗；
3. 检查并发布。

### 重要通知，同时显示首页弹窗

1. 在 `content/library/notices/_index.md` 写完整内容；
2. 在 `data/library/announcement.yaml` 写简短摘要；
3. 设置 `enabled: true`；
4. 为新公告设置新的 `id`；
5. 检查并发布。

### 通知结束，撤下首页弹窗

1. 将 `enabled` 改为 `false`；
2. 根据需要在公告页面补充“维护完成”等结果；
3. 保留历史内容或按实际需要整理；
4. 检查并发布。
