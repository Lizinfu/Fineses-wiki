# 贡献流程与审核职责

本文件定义当前仓库的最小协作流程；具体命令以根目录 [README](../README.md) 为准，字段规则以 [内容模型](content-model.md) 为准。

## 标准流程

```text
任务/问题记录
→ 从 main 创建分支
→ 修改内容或实现
→ 本地预览与校验
→ Pull Request
→ 内容与技术审核
→ 合并 main
→ GitHub Actions 部署
→ 线上抽查
```

## 审核职责

| 角色 | 必须核对的内容 |
|---|---|
| 内容负责人 | 实体边界、名称、正文事实、世界内时间、剧透与公开边界 |
| 内容编辑 | Front Matter、分类、关系、来源、图片替代文字和链接 |
| 技术维护者 | `wiki:validate` / `wiki:build`、模板影响、搜索和部署状态 |
| 发布负责人 | PR 审核结论、CI 通过、线上抽查与必要的回滚决策 |

一人可以兼任多个角色，但不得跳过内容与技术两类检查。

## Pull Request 描述最低要求

- 本次新增/修改了哪些实体或页面；
- 是否新增分类、关系类型、稳定 ID 或 URL aliases；
- 是否存在 `allow_orphan: true`，以及原因；
- 运行过哪些命令及其结果；
- 哪些世界观一致性、移动端或可访问性事项需要审核者人工检查。

## 生成数据

内容变更可能更新 `data/generated/`。这些修改必须由 `npm run wiki:prepare` 或 `npm run wiki:build` 生成，随内容变更一并提交；若仅运行预览导致无语义变化的生成文件改动，应在提交前还原。
