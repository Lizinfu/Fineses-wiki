# 交互式六边形地图实施方案

> 状态：当前权威方案  
> 最近更新：2026-10-19  
> 适用范围：世界总图、国家详图、城市详图、地图生成脚本与地图视觉系统

本文是地图模块唯一的实施方案。它同时记录已经落地的实现、下一阶段架构和资产要求。若本文与 `docs/BUILDER/PLAN.MD` 中的历史设想冲突，以本文和当前代码为准。

## 1. 目标与边界

地图系统最终需要支持：

1. 世界总图表现大陆、海洋、国家、无人区和主要城市；
2. 点击国家标签后在同一地图场景内平滑放大，并在该国范围内渐进显示更细的国家瓦片；
3. 点击城市后继续在同一场景内放大，并在城市范围内显示独立城市瓦片；
4. 不同层级使用不同精度、标签密度和数据文件；
5. 政治区域、自然地形、路线、标签和交互状态相互独立；
6. 世界坐标横向环绕；国家与城市细节层不单独环绕，但随世界场景一起移动；
7. 在不重做边界数据的前提下更换色板、光影、材质和历史时期图层；
8. 在桌面端和移动端保持可用、可读、可检索和可键盘操作。

本项目不建设真实 GIS。地图坐标是世界观内部坐标，不提供现实投影、真实比例尺、导航计算或在线协作编辑功能。

## 5. 政治参考图生成规则

### 5.1 参考图约定

`world-political.png` 必须满足：

1. 黑色或近黑色表示海洋；
2. 每个国家使用稳定、互不接近的纯色；
3. 白色只表示无人区；
4. 海岸和国界保持闭合；
5. 保持 2:1 世界图比例；
6. 允许少量文字和线条，但不应覆盖大面积区域；
7. 不在图中加入需要发布给浏览器的美术纹理。

生成器在每个六边形中心附近进行二维邻域多数采样。当前参数是 7 × 7 采样、颜色容差 74、最低区域票数比例 0.16；对被同一区域六邻格完整包围的单格注记空洞再做一次填补。过大的标签仍会干扰结果，不能依靠这一步恢复多格宽的政治边界。

### 5.2 修改国界的标准流程

1. 编辑 `assets/map-sources/world-political.png`；
2. 若新增颜色，先在 `data/maps/sources.yaml` 注册稳定区域 ID 与 RGB；
3. 运行 `npm run map:generate`；
4. 检查 `data/maps/tiles.yaml` 的来源哈希、陆地数量和区域数量变化；
5. 运行 `npm run wiki:validate`；
6. 在深浅主题下人工检查海岸、国界、无人区和标签落点；
7. 运行 `npm run wiki:build` 和浏览器测试。

不要直接修补 `tiles.yaml`。若单个地区消失，先检查参考图实际颜色和区域映射，再调整 `color_tolerance` 或 `minimum_region_ratio`。不得为了绕过一个局部问题大幅放宽全图容差。

### 5.3 伊琳沃克 L1 来源

原图已从网站可直接发布的 `static/伊琳沃克.png` 移至 `assets/map-sources/inibholc-political.png`。它是 4096 × 2048 的构建输入，上北下南。当前 48 × 28 国家网格先从其蓝色 `[49, 107, 204]` 区域估算国土在详图中的占用范围；**可见政治边界不再直接采用这张单图的轮廓**。生成器用世界图的 `country.inibholc` 掩膜作为唯一边界来源，把父图六边形投影到这一范围，再生成覆盖它的 782 个国土候选瓦片。浏览器按世界父格的真实可见半径生成共享裁剪边界，并在常驻世界图上局部覆盖；其余国家和海域不生成 L1 瓦片。

`data/maps/tiles.yaml` 保存投影的四参数变换、父图来源哈希和单图原始候选数量，便于复现与校验。两图缺少精确地理控制点，当前变换是两者国土外接范围的仿射配准；这会牺牲伊琳沃克单图边缘的局部形状，并非真实地理配准。图中文字只作参考注记，不自动生成地形；白色城市标记只有在 `urban_footprint` 中明确登记后才成为位置锚点。

修改当前可见国界时应编辑世界政治参考图并重新生成数据；修改国家单图会改变 L1 的取景范围，但不会独立改写政治边界。若改世界/国家网格或裁切，必须复核标签锚点、岛屿和邻接关系，且注意瓦片坐标会改变。不得直接编辑 `tiles.yaml`。将来获得统一坐标或控制点后，可在生成器中替换外接范围配准，不需要推翻国家/地点的稳定 ID。

### 5.4 卡夏·欧尔莱特 L2 来源

伊琳沃克单图中的白色圆点是该城唯一可确认的地图位置，约位于原图归一化坐标 `[0.481, 0.725]`，对应当前国家网格约 `[22, 20]`。`data/maps/locations.yaml` 保存地点和实体 ID；`data/maps/sources.yaml` 的 `city.cathair.urban_footprint` 保存父图锚点 `[22, 20]`、暂定半径 `[2.8, 1.5]` 及 L1 父区域 `city.cathair.nation`。生成器首先从伊琳沃克国土中选择一组 L1 六边形作为城区父级范围，再生成 36 × 20 城市网格的 566 片 L2 候选瓦片。L2 使用等比变换保持六边形比例，并按父图真实可见半径裁切到同一条外沿；外沿不会出现两套独立、不重合的边框。变换、父源哈希及父区域瓦片数都随生成数据保存。其外缘仍是**可替换的城区示意范围**，不是正式城市边界。更正城市位置或外缘时编辑源配置并运行 `npm run map:generate`，复核父级瓦片、城外国土和海岸；不手改 `tiles.yaml`。

## 6. 数据语义

### 6.1 必须分离的层

一个瓦片可以同时拥有多种含义。目标数据模型按以下层组织：

1. **基础掩膜**：陆地或水体；
2. **政治层**：国家、无政权地区、行政区、争议区和历史势力范围；
3. **自然层**：高程、山脉、森林、沙漠、湿地、河流和海域；
4. **网络层**：道路、航线、迁徙路线和边境通道；
5. **地点层**：首都、城市、港口、遗迹和地标；
6. **标签层**：大陆、国家、地区、地形和地点名称；
7. **交互层**：悬停、选中、搜索命中和历史时期。

不得把这些信息压缩为单个 `tile_type`，也不得用颜色本身表达政治状态。塔罗萨尔的 `unruled` 是数据字段，国家颜色只是当前视觉主题。

### 6.2 稳定 ID

- 地图：`world`、`nation.inibholc`、`city.cathair`，以及未来扩展的稳定 ID；
- 国家区域：`country.<slug>`；
- 特殊区域：`special.<slug>`；
- 地点：`loc.<slug>`；
- 内容实体：继续引用现有 `params.id`；
- 瓦片：逻辑上使用 `<map_id>:<col>:<row>`；
- 区块：未来使用 `<map_id>:<chunk_col>:<chunk_row>`。

显示名称、中文译名和样式名称都不能替代稳定 ID。

### 6.3 地点坐标

`locations.yaml` 现在同时保存归一化坐标和当前地图的派生 `col` / `row`。归一化坐标是跨精度的权威位置：

```yaml
position:
  x: 0.625
  y: 0.143
```

`x` 和 `y` 均在 0–1 范围内。每张地图的 `col` / `row` 应由归一化坐标派生。这样改变网格密度时无需手工迁移全部城市。世界横向坐标需要按模 1 处理，保证首尾环绕。

伊琳沃克 L1 与卡夏·欧尔莱特 L2 在 `data/maps/features.yaml` 各有 `administrative_regions`、`terrain`、`waterways`、`routes`、`settlements` 五个显式空数组；**要素级字段、绘制逻辑和层级开关尚未实现**。卡夏·欧尔莱特已通过 `locations.yaml` 绑定百科实体、父级国家图、城市详图及 `footprint_status: provisional`，不只是一段画在瓦片上的文字。后续录入道路等要素时需补齐结构校验及测试。

## 7. 三级地图契约

不同层级使用独立瓦片集，但共享一个常驻地图场景、世界坐标和相机。L1/L2 只细化目标范围；不能把 L0 六边形机械放大充当城市图，也不能用页面跳转模拟层级变化。

| 层级 | 入口 | 主要内容 | 环绕 | 渲染策略 |
| --- | --- | --- | --- | --- |
| L0 世界 | 地图门户 | 大陆、国家、无人区、海洋及少量重要地点 | 世界坐标横向 | 常驻 SVG；非当前细化区域继续可见、可交互 |
| L1 国家 | 国家标签、目录或缩放 | 当前试点仅有国土轮廓；后续接入政区、地形、水系、城市和道路 | 随世界场景移动 | 只在目标国土范围覆盖细瓦片；视口区块挂载/回收 |
| L2 城市 | 国家层城市标签、目录或缩放 | 当前仅有暂定城区轮廓；道路、水系、街区、设施与地点待资料 | 随世界场景移动 | 卡夏·欧尔莱特按视口挂载 566 片候选瓦片，并裁切到 L1 城区父瓦片；不覆盖城市外的 L1/L0 |

伊琳沃克世界区域已经注册：

```yaml
detail_map_id: nation.inibholc
detail_status: available
```

当前 L0→伊琳沃克 L1 试点流程：

1. 点击父级标签；
2. 若详图可用，共享相机平滑移向国土并放大；达到进入阈值后，国土细瓦片在同一世界场景内淡入，邻国与海域仍是 L0；
3. 缩小到退出阈值后，L1 淡出并回收区块；两个阈值不同，避免滚轮临界点反复闪烁；
4. 若详图缺失，只聚焦 L0 并显示“详图待补充”；
5. `entity`、`area`、`loc` 保留可分享的聚焦位置；点击已接入的国家会推入浏览器历史，返回键可在同一页面恢复世界概览；旧独立国家 URL 重定向到世界页的该国聚焦链接。

卡夏·欧尔莱特沿用同一机制：点击国家层的城市标签或世界页目录，视野聚焦整片城区，达到 L2 阈值后暂定城区细格淡入；缩小先退出 L2，保留 L1，再缩小退出 L1。L1 进入/退出阈值分别为世界相机倍率 0.62/0.53；L2 为 2.4/2.05。阈值是必要条件，目标区域还必须与当前视窗相交；平移离开目标时细瓦片退出并回收，平移回来时重新加载。它们是当前试点的显示倍率，不是现实比例尺。城市 URL 使用 `loc=loc.cathair`。

当前 URL 的 `entity`、`area`、`loc` 可恢复国家或城市聚焦，但不记录用户手动移动后的精确相机中心与倍率；跨设备打开会重新适配视野。若要分享任意地图视角，仍需稳定的 `view` 地址契约。

第一张 L1 试点采用伊琳沃克，只提取该国蓝色国土。第一张 L2 采用卡夏·欧尔莱特：参考图只给出南部内陆的白色定位点，故当前城区外缘仅是围绕该点的暂定几何示意，不能解释为正式政区、已核实的建成区或道路网络。

### 7.1 世界—国家视觉衔接

世界页同时序列化 L0 和伊琳沃克 L1 掩膜。运行时以生成数据中的 `alignment.transform` 把 L1 本地格点映射回 L0 坐标，并在世界图内部挂载 L1 图层。L1 只包含伊琳沃克的国土候选格，且被同源父图国界裁切；国土外的邻国、海域和标签均保留 L0 实时图层，能够继续拖拽缩放。旧国家页使用的模糊 Canvas 背景不再参与世界页呈现。细节层淡入仅承担瓦片精度变化，不再跨文档切页。

这是 **单场景、多精度局部覆盖**：世界瓦片一直存在，国家细瓦片只在目标国土上方显示。当前配准来自两级掩膜外接范围的仿射变换，边界同源，但**不承诺两张原始参考图的像素级地理配准**。未来的城市锚点、道路和河流应以统一世界坐标或校验过的控制点为准；不能仅依赖外接范围推断精确地理位置。保留稳定 ID，允许替换配准算法。

L1→L2 也使用同一父级边界策略：`nation.inibholc` 掩膜中的 `city.cathair.nation` 是城区外沿的唯一来源；L2 只提供更细的内部瓦片，显示时由这组 L1 六边形投影形成的共享剪裁路径限定。国家层可见的城区外沿和城市层外沿因此严格对齐。它是地图层级边界，不代表现有资料已确认真实建成区。换用正式城市边界时，先更新 L1 父瓦片集合，再由生成器重建 L2；不能分别手绘两条边界。

## 8. 分块与性能

### 8.1 区块格式

伊琳沃克 L1 使用 48 × 28 网格、782 片国土候选格及 16 × 16 视口区块。卡夏·欧尔莱特 L2 使用 36 × 20 网格、566 片暂定城区候选格及 12 × 12 视口区块。两者当前都由页面内的压缩掩膜生成，**不是**独立网络请求或磁盘分片。未来多国、多城导致页面数据超预算时，再拆为独立静态区块文件并按需请求，建议目录：

```text
data/maps/chunks/<map-id>/<chunk-col>-<chunk-row>.yaml
```

只有进入视口和缓冲区的 L1/L2 区块参与实际瓦片节点渲染；离开缓冲区或退出相应缩放层时节点会回收。L0 保持完整 SVG 并横向环绕；L1/L2 通过逐级仿射变换随同一世界相机移动，不独立复制环绕节点。

### 8.2 渲染预算

- L0 维持 8,160 个逻辑格与 10,000 格硬上限；同归属格合并为约 27 个 SVG 路径节点，不复制环绕瓦片节点。后续若需进一步加密，应先评估路径长度与光栅化成本，必要时改为视口分块或 Canvas 基底；
- 当前伊琳沃克 L1 为 782 片候选格，卡夏·欧尔莱特 L2 为 566 片候选格；两层只细化各自范围，不生成邻国和城外格。未来扩展总数据量时，同时挂载的细节格宜控制在约 2,000 个以内；
- L1 邻域直接沿用常驻世界瓦片，不另外复制 SVG 或绘制模糊 Canvas；L1 SVG 裁切使用父图投影边界；
- 指针移动和滚轮的视图更新合并到每帧最多一次；滚轮围绕指针而非画面中心缩放；容器尺寸变化时，未手动调整的视野重新适配，已经手动缩放或平移的视野不被强制重置；
- 缩放快捷键在地图目录与画布间共享，但输入框编辑时不截获；方向键仅在画布内移动。界面显示当前视图层级和镜头所在区域，放大/缩小达到极限时按钮呈禁用态；
- 装饰性连续起伏目前使用单层共享 SVG 分形纹理；真实地形日后可改用少量地图空间纹理或高度图，不为每个六边形创建图片；
- 雾化、颗粒和阴影应用到整组图层，禁止为每个瓦片创建独立 SVG 滤镜；
- 分形噪声滤镜仅在“战术质感”预设且相机静止时运行，并且只在当前最细可见层运行；拖拽、滚轮和相机动画期间暂停，政治配色预设只保留低成本方向光渐变、局部明暗及共享边缘阴影；
- 国家边界应生成合并路径，避免每个边缘瓦片重复描边；
- 标签只显示当前缩放级别允许的项目，且不使用不透明底框；
- 地图脚本和样式继续只在地图页面加载。

## 9. 目标视觉：灰白战术纸图

### 9.1 视觉原则

目标风格是高亮度灰白底图、低饱和政治色、六边形战略网格，以及功能主义、机能风和近未来极简主义的轻量信息界面。地图本身保持浅色以辨别国界，操作区采用深石墨色、细分隔线和少量琥珀色焦点；避免大面积白底卡片和装饰性霓虹。视觉信息按下列顺序叠加：

```text
纸张或雾化背景
  → 连续灰度地形
  → 低对比基础六边形网格
  → 半透明政治覆盖层
  → 合并后的海岸与国界
  → 道路、航线和节点
  → 国家、地区、城市标签与徽记
  → 悬停、选中和搜索状态
```

地形纹理必须跨越多个瓦片连续分布。不能在每个六边形内部独立生成随机纹理，否则会破坏山脉、水系和雾层的连续性。

### 9.2 当前政治语义

- 13 个国家各有独立 `country-*` 样式令牌；
- 国家使用半透明浅色，颜色值只存在于 `atlas.css`；
- 无人区使用白色瓦片和独立描边；
- 海洋使用灰蓝色共享渐变，视觉上低于陆地；
- 环形空洞使用独立 `anomaly` 令牌；
- 国界、政治状态和颜色令牌互不替代。

### 9.3 新视觉预设

现有 `political-pastel` 已保留，`tactical-paper` 已作为可切换的程序化预设加入，不直接覆盖现有主题。参考图的灰白底、低饱和网格、叠层区域与柔和浮雕感被拆为连续分形纹理、舞台环境光梯度、海岸及城区边缘的共享阴影路径、半透明政治色和细节层的缓变明暗。避免对每个六边形施加独立阴影或实时照明滤镜；该类实验曾在高倍率产生条纹伪影，已撤回。以上起伏是视觉材质，不是经核实的山脉或高程。浅色和深色主题分别定义变量。路线、警报语义和徽记仍待后续数据或资产接入：

- 灰白纸张或云雾背景；
- 连续的低对比灰度地形；
- 普通网格 0.3–0.6 像素、低透明度；
- 海岸线高于普通网格但低于国界；
- 国家填充透明度约 10%–25%；
- 合并国界使用低饱和棕红、橄榄或国家专属边色；
- 黑灰信息牌用于普通地点；
- 红色仅用于警报、敌对或当前重点，不能成为常规装饰；
- 大型国家或组织徽记使用 SVG sprite；
- 深色主题使用独立变量，不简单反相浅色地图。

### 9.4 推荐渲染结构

采用混合渲染：

- **Canvas 或优化后的 WebP**：连续地形、纸张、云雾和大尺度光影；
- **SVG**：六边形、政治蒙层、合并国界、路线和可交互区域；
- **HTML**：标签、搜索结果、提示面板和实体链接。

政治参考图仍只在构建时使用。若未来发布地形纹理，应保存到单独的运行时资源目录，不能把带有纯色国界的源图直接当作网站底图。

### 9.5 无图片资产方案

没有新美术资产时，可以用确定性分形噪声、渐变和共享 SVG 滤镜生成灰白雾化底图。该方案足以验证风格、图层顺序和性能，但不能自动产生具有世界观含义的山系、河流和盆地。

因此：

- 视觉原型可以完全程序化；
- 准确地形必须来自地形参考图、高度图或人工地理数据；
- 正式徽记需要 SVG 资产或明确的图形规范。

## 10. 合并国界

当前渲染器已经通过相邻瓦片的区域 ID 生成独立边界路径：

1. 遍历一个国家的所有瓦片；
2. 找出没有同国邻居的六边形边；
3. 将相邻边汇总到同一条海岸或区域对 SVG path（目前仍以多个线段子路径表示，并未做几何简化）；
4. 处理岛屿、内海和世界横向接缝；
5. 按相邻区域对输出 SVG path；
6. 瓦片填充与边界 path 分开绘制。

这一实现避免了共享边界的双重描边，形成可换色、可随国家选择高亮的六边形折线国界；海岸线使用另一条汇总 path。横向接缝由完整世界地图图层的两个 SVG `use` 副本延续，不复制实际瓦片节点。

## 11. 标签、路线和徽记

### 11.1 标签层级

| 视野 | 必须显示 | 可选显示 | 默认隐藏 |
| --- | --- | --- | --- |
| 概览级 | 大陆、海洋 | 暂无 | 国家、地区、地点及小型地形 |
| 区域级 | 国家、特殊区域及 L1 邻国 | 有资料时的一级地区 | 大陆、海洋、城市和设施 |
| 细节级 | 已录入的城市、地点、地形标签 | 有资料时的道路、水系、设施 | 大陆、海洋、国家等上级标签 |

上级标签进入下级时隐藏，不叠加成满屏文字。当前世界相机的概览阈值为 `<0.30`、区域阈值为 `<0.60`，其余是细节标签级；只有目标范围进入视窗，伊琳沃克 L1 才在世界倍率 0.62 进入，国家层显示卡夏·欧尔莱特城市标签，L2 在 2.4 进入并隐藏该上级标签。退出倍率为 0.53 和 2.05，以回滞减少阈值附近闪烁。没有 L1 数据的邻国在放大后仍保留国家名称，不留下标签空档。阈值是 UI 规则，不是地理比例尺。除已核实的城市名称与暂定城区外，尚无地形、街区等细节资料；不虚构标签填充地图。

地图上的国家、地区和地点文字采用透明背景、细线与几何定位符、柔和字影增强对比；HTML 标签预留可选图标容器，未插入图标时不占位。地图目录采用深色索引面板而非白色条目框，仍保留可访问的按钮和档案链接。选中后的档案注释以世界坐标为锚点，屏幕定位只影响注释布局，不改变地点的权威坐标；引线随相机运动更新，不能遮挡当前试点的城市标签。

地点的权威坐标与标签的实际摆放必须分离。标签可以因碰撞而偏移，但地点坐标不能改变。

### 11.2 路线

未来路线数据应保存稳定节点 ID、路径点、类型和显示级别，不直接保存像素路径。世界地图只显示跨国主干线；国家和城市图逐级增加细节。

### 11.3 徽记

国家和组织徽记优先使用 SVG sprite：

- 可以继承颜色；
- 在缩放中保持清晰；
- 不增加大量网络请求；
- 可以在浅色、深色和选中状态下切换样式。

徽记是附加信息，不能替代可读的文字标签。

## 12. 无障碍和交互约束

- 地点目录必须始终是地图的可访问文本入口；
- 颜色不能是区分国家、无人区或政治状态的唯一手段；
- 所有国家、地点和控制按钮需要可见焦点和明确名称；
- 键盘必须能够缩放、重置和激活目录项；
- 选中状态通过 `aria-pressed` 或等价语义暴露；
- 地图动画尊重 `prefers-reduced-motion`；
- 标签在两种主题下满足可读对比度；
- Canvas 只承担视觉底层，实体链接和核心交互不能只存在于 Canvas；
- 无 JavaScript 时继续显示地点目录与条目链接。

- 是否有正式徽记与视觉禁用项。

当前试点只验收国土轮廓、瓦片数、同场景层级和交互。专题图层的开关与检索须在可靠资料到位后实现，不把原图文字或白色圆点当作已核实地名。

### 阶段 D：卡夏·欧尔莱特城市试点

已完成：根据伊琳沃克参考图的白色城市标记建立 L1 位置锚点；在国家层生成暂定城区父级瓦片，生成 566 片 L2 候选瓦片并用同源父级外沿裁切；建立 L2 校验和空专题接口；在同一场景中从国家层继续放大到城市层，缩小时逐级退出。城市当前是一片瓦片化城区，不是单点标记。

尚待资料：正式城区边界、可核实的街区和道路、水系、地形、城区内地点。收到边界后替换 `data/maps/sources.yaml` 中的 `urban_footprint` 示意参数并重新生成，不应直接改 `tiles.yaml`。专题数据录入前先确立要素字段与缩放级别。除地图页面外不加载城市数据。

## 14. 需要补充的资产

### 14.1 L1 最低要求

每张国家级**国土轮廓**参考图至少需要：

- 明确目标国家范围；
- 北向或方向说明；
- 海岸与内陆水体；
- 与邻国连接处的边界延伸。

伊琳沃克已经满足这一阶段的轮廓输入。要开展下一阶段的地理内容录入，需要另补政区边界、城市坐标和命名、主要水系/地形；这些不是当前国土瓦片生成的先决条件。

推荐将政治边界、自然地形、文字说明和视觉纹理分层提供。若只能提供一张合成图，也应保证各类区域颜色稳定且文字不遮挡大面积边界。

### 14.2 战术纸图正式美术

若要从当前程序化原型升级为准确版本，优先补充：

1. 世界高度或灰度地形图；
2. 山脉与主要水系图层；
3. 国家和组织徽记 SVG；
4. 路线、港口和战略节点资料；
5. 对灰白、棕红、橄榄绿等视觉倾向的确认。

## 15. 验收与质量门禁

每次地图变更至少检查：

### 数据

- 生成文件与参考图哈希一致；
- 国家与无人区掩膜互斥且位于陆地内；
- 地点位于目标地图有效范围；
- 标签锚点在地图范围内；
- 实体引用存在；
- 伊琳沃克与德诺尼塞的陆界和共同海湾约束仍成立；
- 世界横向接缝没有不连续边界。

### 视觉

- 13 个国家保持可区分；
- 无人区保持白色陆地语义；
- 海洋不会与无人区混淆；
- 深浅主题均能辨认海岸和国界；
- 全图视野不过度显示细网格和小标签；
- 放大后地形纹理连续，不按瓦片断裂；
- 选中与悬停不抹掉国家身份色。

### 交互与性能

- 桌面和移动端可以拖拽、缩放和重置；
- 键盘交互与焦点可见；
- URL 状态可以恢复；
- 非地图页面不加载地图脚本和样式；
- L0 逻辑瓦片不超过 10,000，实际合并路径节点保持在百级以下；
- L1/L2 只保留可见区块和缓冲区；
- 不使用每瓦片独立图片或重型滤镜。

### 命令

```powershell
npm run map:generate
npm run wiki:validate
npm run wiki:build
$env:PLAYWRIGHT_CHANNEL='chrome'; npm run test:browser
```

仅检查参考图与生成数据是否同步时使用 `npm run map:check`，不需要先写入文件。

## 16. 维护原则

1. 当前事实和后续地图路线只维护在本文；
2. `PLAN.MD` 仅保留全项目历史架构和指向本文的摘要；
3. 政治参考图、发布用地形纹理和网站截图属于不同资产，不能混用；
4. 生成数据禁止手工修改；
5. 数据语义不得依赖 CSS 颜色；
6. 新层级必须先有数据契约和校验，再批量录入内容；
7. 高精度通过独立地图和区块加载实现，不通过无限放大 L0；
8. 任何视觉升级都必须保留目录、实体链接和无脚本回退。
