# 参考图驱动的六边形世界地图

世界地图采用“参考图生成数据、浏览器绘制瓦片”的两阶段结构。参考图只参与本地生成，不会作为网站运行时底图加载：

```text
world-political.png
        ↓ npm run map:generate
data/maps/tiles.yaml
        ↓ Hugo + TypeScript
SVG 六边形地图
```

地图相关文件的职责如下：

- `assets/map-sources/world-political.png`：仅供构建使用、不会直接发布的陆地与国界参考图；
- `data/maps/sources.yaml`：图像采样、裁切和目标网格配置；
- `data/maps/tiles.yaml`：自动生成的陆地瓦片行区间，不应手工修改；
- `data/maps/areas.yaml`：大陆多边形、生成区域元数据、标签落点与视觉令牌；
- `data/maps/topology.yaml`：必须长期成立的陆界、海湾等空间关系约束；
- `data/maps/layers.yaml`：地图视野、缩放和视觉模式；
- `data/maps/locations.yaml`：地点与实体引用；
- `scripts/generate-hex-map.mjs`：参考图到瓦片数据的生成器；
- `assets/scripts/map.ts`：浏览器端 SVG 与交互；
- `assets/styles/pages/atlas.css`：颜色、光影和材质。

## 当前世界总图

当前总图使用 `64 × 28` 个平顶六边形，共 1,792 个逻辑瓦片。它与 2:1 参考图的视觉比例基本一致，同时仍低于单个 SVG 的 2,000 节点预算。当前参考图生成 626 个陆地瓦片，其中各国家和白色无人区拥有互斥的生成掩膜。

世界采用横向环绕语义。当前总图从左到右依次表现库库尔坎、克里希达、齐黄大地；两端白色陆地按同一世界的首尾连续区域理解。当前交互层会用两个 SVG `use` 引用补齐左右相邻视图，并在拖拽时循环水平偏移；它不会复制 1,792 个六边形节点。后续区块化时也应把横向首尾视作相邻区块。

该规格仍是世界概览层，不应承担城市街区级精度。主要城市可以通过独立标记精确定位；更高精度地理应使用后文的分级地图和可见区块加载。

单个 SVG 地图当前硬限制为 2,000 个六边形。这个限制约束一次性进入 DOM 的数量，不限制未来地图数据的总瓦片数。

## 从参考图重新生成

参考图应满足：

1. 黑色或近黑色表示海洋；
2. 每个国家使用稳定、纯度较高且互不接近的填充色；
3. 白色统一表示无人区，不与页面背景语义混用；
4. 国界使用深色线条，保持海岸与国界闭合；
5. 保持 2:1 世界图比例。文字可以保留，生成器会通过六边形邻域多数采样忽略文字造成的局部黑色孔洞。

更换参考图或调整采样参数后运行：

```powershell
npm run map:generate
npm run wiki:validate
```

`npm run map:check` 会重新计算结果并与 `data/maps/tiles.yaml` 比较。参考图改变但未重新生成时，构建会失败，避免网站继续使用过期地图。

生成配置位于 `data/maps/sources.yaml`：

```yaml
sources:
  world:
    input: "assets/map-sources/world-political.png"
    output: "data/maps/tiles.yaml"
    grid:
      columns: 64
      rows: 28
    region_sampling:
      samples: 7
      color_tolerance: 74
      minimum_region_ratio: 0.16
    regions:
      country.inibholc:
        color: [49, 107, 204]
      special.uninhabited:
        color: [255, 255, 255]
```

关键参数：

| 字段 | 作用 |
| --- | --- |
| `crop` | 排除参考图边框和装饰区域，数值为图像比例 |
| `region_sampling.samples` | 每个六边形附近的二维采样密度 |
| `region_sampling.color_tolerance` | 像素与登记 RGB 颜色允许的欧氏距离 |
| `region_sampling.minimum_region_ratio` | 区域获得一个六边形所需的最低邻域票数比例 |
| `regions` | 稳定区域 ID 到参考图 RGB 填充色的映射 |

如果区域突然消失，先确认参考图使用的实际填充色与 `regions` 一致，再检查裁切和 `color_tolerance`。不要仅为修复一个文字标签而大幅提高容差，否则相邻颜色可能被错误合并。

## 生成瓦片格式

`data/maps/tiles.yaml` 使用按行区间压缩：

```yaml
land_rows:
  - row: 12
    ranges:
      - [8, 19]
      - [31, 35]
```

它表示第 12 行的 8–19 列和 31–35 列为陆地。相同格式可以复用于国家、行政区、地形和历史势力范围，避免为每个六边形存储一个冗长对象。

`area_masks` 使用相同的 `tile_rows` 压缩格式记录每个国家与无人区。网站运行时直接读取这些生成掩膜；参考图本身不会被下载到浏览器。

瓦片坐标采用平顶六边形的 `odd-q` 偏移坐标。稳定引用格式为 `map_id + col + row`；区域和地点数据不得依赖 SVG 节点顺序。

## 地点与主要城市

地点位于 `data/maps/locations.yaml`：

```yaml
locations:
  - id: loc.muocils
    entity_id: nat.muo
    map_id: world
    label: "莫尔索斯"
    kind: region
    col: 40
    row: 4
```

`col` 和 `row` 必须落在生成的陆地瓦片上。地点标记是独立 HTML 链接，不需要把城市本身做成特殊地形瓦片。因此，即使世界概览层保持 1,792 格，也可以显示和检索大量主要城市。

未来应给地点增加归一化世界坐标作为权威位置，`col` / `row` 只作为当前层级的派生索引。这样提高网格密度时不必手工迁移所有城市。

## 国家、地区和地形覆盖层规划

基础陆地、区域归属和标签必须保持分层：

1. **基础掩膜**：只回答陆地或海洋；
2. **政治覆盖层**：国家、行政区和争议区域；
3. **自然覆盖层**：山脉、沙漠、森林、盆地和海域；
4. **标签层**：国家名、地区名和地形名；
5. **地点层**：首都、城市、遗迹和地标。

覆盖层建议继续使用 `land_rows` 相同的行区间编码，并包含：

```yaml
id: region.example
map_id: world
kind: country
entity_id: nat.example
style_token: region-neutral-01
label_anchor: [24, 11]
tile_rows: []
```

`style_token` 应引用有限的 CSS 色板，而不是在内容数据中写任意颜色。一个瓦片可以同时属于政治区域和自然地形；渲染器按层级与透明度合成，不应把所有信息压进单一瓦片类型。

### 当前政治层

国家和无人区边界由 `world-political.png` 的颜色直接生成，`data/maps/areas.yaml` 只保存实体引用、标签锚点和视觉令牌。大陆标签与环形空洞仍使用轻量多边形，因为它们不是参考图中的独立颜色区域。当前数据包含：

- 库库尔坎、克里希达、齐黄大地三个大陆标签；
- 13 个现存国家实体的参考图生成范围；
- 所有白色陆地组成的无人区掩膜与环形空洞；
- 塔罗萨尔实体，其 `political_status` 为 `unruled`，表示保留地理与资料库身份但不存在现行政权。

资料中未出现的历史国家不进入当前政治图。伊琳沃克与德诺尼塞同时具有陆上接壤和共同海湾接触；这项关系记录在 `data/maps/topology.yaml`，校验器会在颜色掩膜生成后同时检查两种接触是否存在。

点击国家标签时，当前页面会聚焦它在世界总图上的范围、更新可分享的 `entity` 查询参数，并提供资料条目入口。国家详图尚未伪造：界面会明确提示“详图等待独立参考图”。

若要修订国家边界，应修改 `world-political.png` 中对应的纯色范围，再运行 `npm run map:generate`。标签位置只需调整 `data/maps/areas.yaml` 的 `label_anchor`。校验器会检查生成掩膜、实体引用、标签落点、陆海类型以及拓扑关系。

## 分级地图与切换契约

不同层级使用独立地图与独立瓦片集，不把世界总图机械放大成城市图：

| 层级 | 点击入口 | 数据职责 | 当前状态 |
| --- | --- | --- | --- |
| 世界 | 地图入口 | 大陆、国家、特殊大地理区、主要城市 | 已实现 |
| 国家 | 国家标签 | 国界、一级地区、主要地形、城市 | 数据契约预留，等待参考图 |
| 城市 | 城市标记 | 城区、水系、道路与重要地点 | 数据契约预留，等待参考图 |

后续每张详图应拥有独立 `map_id`，并在父级入口记录 `detail_map_id`。交互流程固定为：点击父级标签 → 若详图存在则加载对应瓦片数据并切换层级；若不存在则保持世界聚焦并显示待补充状态。返回上级时保留父地图的缩放中心，避免重新定位。

推荐国家和城市数据按 `16 × 16` 或 `24 × 24` 六边形区块保存。横向世界图的最左与最右区块需要互为邻居；国家和城市详图默认不环绕，除非该地图自身明确配置 `wrap_x: true`。

## 面向城市精度的瓦片化路线

不要把完整高精度世界地图一次性渲染为数万个 SVG 节点。推荐分级：

| 层级 | 建议规模 | 用途 | 渲染策略 |
| --- | --- | --- | --- |
| L0 世界概览 | 64 × 28 | 大陆、国家和主要地形 | 当前完整 SVG |
| L1 世界细图 | 约 108 × 60 | 国家边界、主要城市和岛链 | 按视口加载区块，或 Canvas |
| L2 区域详图 | 独立区域网格 | 城市群、道路、河流 | 独立数据文件，按需加载 |

实现下一层前需要至少一张国家级参考图。建议先以伊琳沃克作为试点，因为它同时包含大陆、岛屿、海湾和陆上边界，足以验证生成器、区块加载和标签层。城市级再以一座资料较完整的主要城市作为第二个试点。每张参考图至少应明确海岸/水体、目标范围和北向；若能额外提供政治边界与主要地形分层图，可直接建立覆盖层而不用把视觉细节烘焙进基础瓦片。

L1 可以由同一参考图生成，但应按固定区块保存，例如 `16 × 16` 或 `24 × 24` 瓦片一块。缩放时只加载视口附近区块。这样“总数据量”和“当前 DOM 数量”彼此独立，能够继续提高精度而不突破页面性能边界。

城市名称不应依赖六边形中心摆放；使用归一化坐标定位，再通过标签碰撞检测决定显示层级。世界概览仅显示首都和最重要城市，放大后再逐级显示其他城市。

## 政治色板、海洋层次与扩展接口

地图视觉配置与瓦片数据分离：

```yaml
appearance:
  palette: political-pastel
  relief: subtle
  material: paper
```

当前世界图使用三类互不复用的视觉语义：

- 13 个国家各自拥有一个 `country-*` 样式令牌，以半透明浅色色块显示；政治状态（例如塔罗萨尔的 `unruled`）仍由独立数据字段表达，不再借用颜色令牌；
- 无人区使用不透明白色瓦片和独立描边，在深浅主题下都保持“陆地但无国家归属”的含义；
- 海洋使用独立 SVG 纵向渐变和较深边线形成下沉感，不与陆地或无人区共享填充色。

颜色值只存在于 `assets/styles/pages/atlas.css`，国家归属只存在于生成后的瓦片掩膜和 `data/maps/areas.yaml`。因此后续可以整体替换色板、调整透明度或加入材质，而不用重新描绘国界。新增国家时必须注册新的 `country-*` 令牌，并由 `scripts/validate-maps.mjs` 校验，避免两个国家意外复用同一颜色。

后续可以在不重新生成海岸掩膜的情况下加入：

- 区域半透明色块和边界；
- 高程、湿度、植被及气候字段；
- 基于高程的光照方向和阴影强度；
- 纸张、石板、金属或终端网格材质；
- 历史时期图层切换。

材质优先使用 CSS 渐变、SVG pattern 或轻量滤镜，不要为每个六边形加载独立图片。

## 提交前检查

1. 运行 `npm run map:generate`；
2. 运行 `npm run wiki:validate`；
3. 运行 `npm run wiki:build`；
4. 对照参考图检查大陆、岛屿和海岸缺口；
5. 确认地点仍位于陆地瓦片；
6. 检查桌面端和移动端拖拽、缩放及地点定位；
7. 深浅主题下保持海岸和覆盖层可辨认。
