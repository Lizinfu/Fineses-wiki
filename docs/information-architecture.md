# 信息架构（当前约定）

## 内容目录与读者导航分离

`content/` 以实体类型为一级 Section：国家、人物、历史、地区、组织、概念、物品、文献和生态等。实体不应因为隶属某个国家、组织或阵营而移动或复制；归属与影响通过关系表示。

读者侧入口由 `content/portals/` 和 `data/navigation/portals.yaml` 定义，可聚合多个 Section。因此调整门户不应要求迁移实体文件。

## 页面层级

目标层级不超过四层：

```text
首页 → 门户 → 分类/集合 → 实体主页面 → 实体章节（可选）
```

`_index.md` 用于 Section 或可以拥有子页面的 Branch Bundle；`index.md` 用于只包含正文和媒体的 Leaf Bundle。复杂国家或区域可使用 `_index.md` 作为实体根页，再添加章节；普通章节不应为“占位”而提前创建空文件。

## 页面发现路径

重要公开实体至少应能通过两种方式发现：门户/目录、taxonomy、全文搜索、正文实体引用或关系/反向链接。内容增长时优先增加真实关系和分类，而不是复制同一段正文。
