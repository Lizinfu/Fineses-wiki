# 正文检索规则与维护

## 当前匹配规则

检索中心只搜索公开 Markdown 页面的正文。文档标题和类别用于展示结果，不参与匹配；导航、信息框、关系列表和其他模板附加信息也不进入索引。索引的正文来自 Hugo 的 `.Plain`，因此包含 Markdown 正文渲染后的文字及正文中的小节标题、图片说明和短代码文字。

输入按空白字符拆分为一个或多个关键词，重复关键词只计算一次。每个关键词是连续字符串；一篇文档必须同时包含全部关键词，词序与距离不限。英文字母忽略大小写，英数字和常用 ASCII 符号的全半角形式等价；不做分词、模糊匹配、同义词扩展或跨段落拼接。没有关键词时不列出结果。

每篇文档只出现一次。按最早命中位置、标题和 URL 稳定排序；结果数量是满足全部关键词的文档数量。摘要从命中位置提取原文，重叠片段合并，关键词高亮。

## 生成与检查

`layouts/home.searchindex.json` 在 Hugo 构建期间生成 `public/search-index.json`。索引条目包含 URL、标题、正文和供日后筛选使用的类别字段。`assets/scripts/search-core.mjs` 实现匹配规则；`assets/scripts/search.ts` 负责浏览器加载、输入、结果及摘要。不要手工修改 `public/search-index.json`。

运行 `npm run wiki:build` 检查索引格式、URL 与站点目标；运行 `npm run test:browser` 检查实际检索界面。新增页面模板时，确认其正文属于公开 Markdown 内容并出现在索引中。若只是修改正文，Hugo 会在下一次构建时重建索引。

## 后续分类筛选

索引已保留 `kind` 和 `section` 展示字段。新增分类筛选时，应先完成正文关键词匹配，再对命中集合应用类别条件；不能改变关键词的连续包含与全部命中规则。内容量明显增长后，再评估分块或候选索引，最终结果仍需逐篇执行相同的正文匹配。
